# 审批节点拍板清单（业务方一页纸）

> **为什么需要拍板**：系统现有的审批节点（申请两级、合同/授权 50 万阈值）是**开发阶段的占位假设**——PRD 第 1478 行明确"采购申请审批链和超预算审批流程的具体节点"待业务+财务+招采确认，PRD 未定。真实审批引擎（P4）已按"节点全部配置化"开发，**拍板后只改配置、不改代码**；但配置的初始值必须有人拍板。**未拍板的项，将按"我方建议"默认值直接上线。**

**拍板方式**：逐项打勾或改选项，建议一次会议拍完（预计 30 分钟）。每项含影响范围一句话，改选项不影响工期（配置化）。

---

### 1️⃣ 采购申请审批链（几个节点、谁审）

- **问题**：采购申请提交后走几级审批？
- **选项**：
  - A. 两级：部门负责人 → 采购部（现状占位）
  - B. 一级：采购部直接审
  - C. 三级及以上：部门负责人 → 采购部 → 分管领导（请补充）
- **我方建议**：**A**。与现有实现和 PRD 角色职责一致，改动成本 0；小额高频采购建议靠"日常采购免审批链路"分流而非压缩申请审批。
- **影响范围**：审批引擎节点配置表 1 行。

### 2️⃣ 超预算升级审批（谁给超预算放行）

- **问题**：采购申请/定标超预算被拦截后，升级审批走谁？
- **选项**：
  - A. 一级：财务负责人（建议）
  - B. 二级：财务负责人 → 分管领导
  - C. 超预算比例分档（如 ≤10% 财务、>10% 加分管领导）——请给比例
- **我方建议**：**A**。PRD 定位预算审批归财务；分档是增强项，可后续在配置表加节点，不需现在定。
- **影响范围**：BUDGET 审批流节点配置。

### 3️⃣ 各节点审批人角色映射（系统按角色解析到人）

- **问题**：以下节点分别由哪个角色/岗位审批？（系统按角色解析，多人=任一人可审）
- **需逐项确认**：
  | 节点 | 我方建议（默认角色） | 业务确认 |
  |---|---|---|
  | 申请审批·第 1 节点 | 部门负责人（申请人所在部门） | ☐ |
  | 申请审批·第 2 节点 | 采购部（招采负责人） | ☐ |
  | 超预算审批 | 财务负责人 | ☐ |
  | 定标审批 | 采购负责人 | ☐ |
  | 合同审批 | 采购负责人（超阈值加第 2 节点=？） | ☐ |
  | 履约调整 / 结算审批 | 采购负责人 | ☐ |
  | 供应商资质审批 | 招采人员 | ☐ |
  | 日常采购超授权确认 | 部门负责人 或 采购负责人（现二选一，需定一） | ☐ |
- **我方建议**：按上表默认；若某角色多人任职，默认**任一人审批即可**（或签），如需多人会签请标注。
- **影响范围**：审批人解析配置；角色须在系统"系统角色"中先建好。

### 4️⃣ 金额阈值（两个 50 万都是占位数）

- **问题**：①定标/合同超过多少金额需要升一级审批？②日常采购单笔授权额度是多少（超过须负责人确认）？——现状均为 **50 万元占位**，无业务依据。
- **选项**：A. 维持 50 万　B. ____ 万（请填）　C. 分档（请给档位）
- **我方建议**：两项**分开拍板**（不是同一个数）。建议 ①合同升级阈值 50 万；②日常采购单笔授权额度明显更低（日常采购本为小额高频，50 万占位偏宽，建议业务给实际数，如 5–10 万）。
- **影响范围**：两处配置值，改数即生效。

### 5️⃣ 履约调整免审口径（必须确认，存在历史口径冲突）

- **问题**：订单履约调整是否"小额免审"？早期设计曾有"合同金额 5% 以内免审"，**后经 PRD 核对判定与 PRD 冲突并已取消**——PRD 第 776 行"履约调整进入审批单据中心"无任何免审阈值，现实现为**金额 1 元也要走审批**。
- **选项**：
  - A. 维持全部走审批（PRD 口径，现状）
  - B. 恢复免审阈值：调整金额 ≤ 合同金额 ____ % 免审直生效
- **我方建议**：**A**。PRD 原文无免审通道；免审会让调整金额绕过审批留痕，预算/合同占用差额失去管控点。若业务坚持 B，属于超出 PRD 的新需求，需重新评审影响面。
- **影响范围**：A=零改动；B=需新开发免审分支+重开评审。

### 6️⃣ 审批通知渠道与时效

- **问题**：审批待办/结果如何通知相关人？
- **选项**：
  - A. 站内通知+列表红点即可（本期交付）
  - B. 需要短信/企业微信/钉钉推送（新增需求，排 v1.x）
- **我方建议**：**A**。PRD 将外部渠道列在后续版本；站内红点+待办列表已满足一期闭环，B 属加需求会影响排期。
- **影响范围**：A=零影响；B=新增外部通道开发与账号申请。

### 7️⃣（可选）高频补货自动通过授权开关

- **问题**：普通高频补货（价格、数量固定）是否需要"按配置自动通过授权校验"能力？（主流程 docx 允许，但不跳过合同/预算/留痕）
- **选项**：A. 暂不需要（建议）　B. 需要，默认关　C. 需要，默认开
- **我方建议**：**A 或 B**。建议先留配置位默认关，运行一个季度后按实际高频单量决定；避免上线初期绕过人工确认。
- **影响范围**：A/B 均不改变本期交付内容；C 会改变日常采购默认行为。
