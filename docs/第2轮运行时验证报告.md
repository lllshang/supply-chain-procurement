## 3. P1-5 采购申请建单注入（PurchaseApplyController.save）

**判定：FAIL ❌（源码 Bug，转工程师修复）**

### 验证方式
以 `qa_dept` POST `POST /api/v1/purchase-requests`，请求体**故意省略** `dept_id / applicant_id / apply_no / status`：
```json
{"title":"QA冒烟测试-部门隔离","type":0}
```
预期：后端注入 dept_id=2、applicant_id=2、apply_no=PA+时间戳、status=DRAFT。

### 实际结果
```
HTTP 500
{"code":1000,"message":"系统异常，请稍后重试","traceId":"..."}
```

### 根因（应用日志）
```
327 ERROR ... c.dzgylxt.common.GlobalExceptionHandler : 系统异常 uri=/api/v1/purchase-requests
329 org.springframework.core.annotation.AnnotationConfigurationException:
    Found more than one annotation of type interface org.springframework.security.access.prepost.PreAuthorize
    attributed to public com.dzgylxt.common.R com.dzgylxt.controller.PurchaseApplyController.save(com.dzgylxt.entity.PurchaseApply)
    Please remove the duplicate annotations and publish a bean to handle your authorization logic.
```

### 缺陷定位（文件:行号）
- `backend/src/main/java/com/dzgylxt/controller/PurchaseApplyController.java:20` —— 重写方法上再次声明 `@PreAuthorize("isAuthenticated() and @authz.hasAnyPerm(authentication)")`
- `backend/src/main/java/com/dzgylxt/controller/BaseController.java:58` —— 父类 `save` 已声明同名 `@PreAuthorize`

二者叠加，Spring Security 在方法安全元数据分析阶段发现**同一方法存在两个 `@PreAuthorize`**，直接抛 `AnnotationConfigurationException`，请求在到达方法体之前即失败。因此 **PurchaseApplyController.java:24-35 的注入逻辑（deptId/applicantId/applyNo/status）从未被执行**，建单必然 500。

> 影响范围：已排查 `controller/` 下**仅 `PurchaseApplyController` 重写了 `BaseController` 方法**（grep `@Override` 仅此一处），该重复注解 Bug **作用域孤立**于 `save` 一处。其余 CRUD 端点（page/getById/update/remove，均源自 BaseController 未重写）工作正常（见 §2、§4）。
>
> 注：请求体 `type:0` 合法（`PurchaseApplyType.STANDARD(0,...)`）。一旦工程师移除重复注解，注入逻辑应能正常落库（逻辑本身经代码审查无明显问题，但本轮因 500 未触达，建议修复后回归）。

**路由判定：Send To Engineer（Alex）** —— 测试断言正确（应注入并 200），实现有误（重复注解阻断请求）。
