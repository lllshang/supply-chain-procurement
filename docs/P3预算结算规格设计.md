## 0. 结论先行

P3 交付三件事：① **清掉 D3**——把 P2 预算软校验升级为**硬控制**（校验 + 占用 + 拦截 + 超预算升级审批，`budget_line.used_amount` 开始真实写入，新增占用流水表保证全生命周期留痕与对账）；② **清掉 D8**——结算（物料/服务/阶段/尾款）与付款登记/台账/对账，驱动订单 `SETTLED / PAID` 状态真实流转，服务结算取数 P2 已留的 `service_assess.deduct_amount`；③ **成本管理**——价格审核与价格库、按部门成本核算归集。

- **关键裁量（详见 §8，均给建议）**：占用时点建议**申请提交即预占用**（超预算→拦截并升级审批 bizType=`BUDGET`）；释放/核销按 §5 全生命周期规则表执行；付款回写建议**财务手动登记确认 + 凭证**（一期不直连财务）；价格库与 P1 `price_rule` **两套分工**（事前规则 vs 事后沉淀）不合一。
- **审批**：统一走 `ApprovalGateway` 本地桩（即审即过），新增 3 个 bizType：`BUDGET`（超预算升级）、`SETTLEMENT`（结算审批）、`PAYMENT`（付款财务审核）；完整审批中心 UI 属 P4，本阶段状态机按真实流转设计。
- **实体映射**：复用 `budget_header / budget_line / settlement / payment` 4 个已有实体（加字段），**新建 2 个实体**：`budget_occupy_log`（预算占用/释放/核销流水，对账依据）、`price_history`（价格库）。
- **明确排除**：报表中心（行 45–47）业务需求未提供，**真阻塞**（见 §8 Q8）；不直连财务（经适配层，P6）；不做 WMS 库存结存。

## 2. 产品目标（Product Goals）

1. **预算真实可控**：预算从"提示"变"闸门"——提交即占用、超预算拦截并升级审批、全程流水留痕、每日对账校准，杜绝预算穿透与假占用。
2. **结算付款闭环**：从订单/到货单一键发起结算（物料按验收数量、服务按考核扣款），付款线下执行、系统登记回写，形成可对账的资金台账并驱动订单收口（SETTLED/PAID）。
3. **价格与成本可治理**：历史价格沉淀为价格库（审核入库），采购成本按部门/科目/月份归集可视，为成本分析与后续报表中心备数。

## 4. 需求池（按 P0 / P1 分级）

> 每条含：功能描述、验收标准（AC）、字段与状态机、**与 P2 单据的联动点**。单据编号见 §7。

### 4.1 预算硬控制（行 37–38 · 清 D3）

#### P0 · R-BUD-10 预算校验与占用（软校验升级）
- **功能描述**：采购申请提交时，对"部门+科目（+可选项目）"执行预算校验；通过即**预占用**，不足则**拦截**并生成超预算升级审批；审批通过后按超支金额占用。
- **AC**：① 校验/占用/写流水在**同一 DB 事务**内，对 `budget_line` 行锁（`SELECT ... FOR UPDATE`）+ Redis 分布式锁（`budget:lock:{deptId}:{subjectId}`）+ `version` 乐观锁兜底（对齐架构 2.2）；② 占用成功写 `budget_occupy_log`，`used_amount` 同事务更新；③ 超预算→`budget_status=2`，状态停在 `BUDGET_PENDING`，经 `ApprovalGateway`（bizType=`BUDGET`）发起升级审批：通过→占用并流转 `PURCHASE_PENDING`，驳回→回 `DRAFT`（不占用）；④ 校验口径默认**年度**（`period=0` 行）——月度仅台账展示（见 Q1b）；⑤ P2 软校验方法读数逻辑复用，入口替换，**契约不变**。
- **字段与状态机**：`budget_line` 结构不变（`amount/used_amount/version/period` 已有）。**新建 `budget_occupy_log`**：`budget_line_id, biz_type(APPLY/AWARD/ORDER/SETTLEMENT/ADJUST), biz_id, action(0占用/1释放/2核销/3调整), amount, balance_before, balance_after, operator, remark`。
  - 联动点：`purchase_apply.submit()` 的软校验入口替换为硬控；`BUDGET_PENDING` 节点语义激活；`budget_status` 0/1/2 语义不变。
- **实体映射**：`budget_line`（不变）；**新建** `budget_occupy_log`。

#### P0 · R-BUD-11 预算释放与核销（全生命周期规则见 §5）
- **功能描述**：申请驳回/作废、订单取消/变更减量、履约调整等场景自动回冲占用；结算完成做核销（占用转核销，`used_amount` 总额不变、构成转移）。
- **AC**：① 所有释放/核销动作**必须**写 `budget_occupy_log`（负向 action）；② 释放金额 ≤ 该单据累计占用余额（不足则按余额释放并告警）；③ 申请关闭（`FULL_ORDER` 或作废）时释放未转单余量占用；④ 核销不改变 `used_amount`，仅改变构成（占用→核销），供执行台账区分"已用未结/已结"。
- **实体映射**：`budget_occupy_log`；联动 P2 状态机（申请驳回/订单取消/订单变更）。

#### P0 · R-BUD-12 预算执行台账与超预算审批联动
- **功能描述**：预算执行台账（部门×科目×月份：预算额、占用、核销、可用、执行率）；超预算审批任务列表与处理；每日对账任务校准。
- **AC**：① 台账数据源=`budget_header/budget_line/budget_occupy_log` 聚合，经数据权限过滤；② 可用余额=Σ(amount)−used_amount，执行率=used/amount；③ 对账任务：每日比对 `Σlog(占用−释放) 与 used_amount`，不一致告警（对齐架构 2.2-R2）；④ 超预算审批列表走统一审批入口（P4 换 UI 无感）。
- **实体映射**：查询视图，无新表。

#### P1 · R-BUD-13 月度调整
- **功能描述**：按科目×月份调整预算额（调增/调减），全程留痕。
- **AC**：① 调增直接生效；② **调减校验：调整后 `amount ≥ used_amount`**，否则拒绝；③ 单次调减超阈值（默认科目月度额 20%，可配置）走 `ApprovalGateway`（bizType=`BUDGET`，action=调整）；④ 每次调整写 `budget_occupy_log(action=3)` 记录前后值。
- **实体映射**：`budget_line.amount` 变更 + log。

### 4.2 结算与付款（行 16–17 · 清 D8）

#### P0 · R-STL-01 物料结算（按验收结算）
- **功能描述**：从**订单或到货单**发起物料结算：自动带出验收合格入库数量（`arrival_item.qty_stored`）× 订单价格，生成结算单，提交结算审批。
- **AC**：① 发起入口校验：订单 `RECEIVED/PARTIAL_RECEIVED`（部分到货可部分结算）或到货单 `STORED/PARTIAL_STORED`；② 结算数量 ≤ 已入库合格数量累计，重复结算拦截；③ 结算金额=Σ(结算数量×订单明细价)（基本单位口径）；④ 与合同比对展示（累计结算 ≤ 合同金额提示，超出仅告警，硬约束仍在下单侧）；⑤ 结算审批经 `ApprovalGateway`（bizType=`SETTLEMENT`），通过置 `SETTLED` 并**触发预算核销**（R-BUD-11）；⑥ 一订单可多次结算（分批），全部结清后订单→`SETTLED`。
- **字段与状态机**：`settlement`（已有 `order_id/arrival_id/type/amount/status/remark`）**+ `settle_no`、`+ settled_qty_base`（累计结算数量）、`+ deduct_amount`（服务扣款，物料为 0）、`+ contract_id`（追溯，nullable）**。
  - 状态机（`SettlementStatus`）：`PENDING（待审批）→SETTLED（已结算）/ PARTIAL（一单多批次时未结清的中间态按订单维度展示，单据级保持 PENDING→SETTLED）`。
- **实体映射**：`settlement`(+4)；联动 `arrival_item / order_item / contract`。

#### P0 · R-STL-02 服务结算（按质量考核）
- **功能描述**：服务订单按验收考核结算：结算金额=订单金额−Σ(`service_assess.deduct_amount`)，扣款明细留痕可追溯。
- **AC**：① 仅服务订单（`order_type=1`）可发起服务结算；② 自动汇总该订单全部考核扣款并展示明细（考核单号/评分/扣款/依据）；③ 扣款总额 > 订单金额时结算金额取 0 并告警；④ 其余流程同 R-STL-01（审批、核销、订单收口）。
- **字段与状态**：复用 `settlement.type=SERVICE` + `deduct_amount`；考核明细从 `service_assess` 取数（P2 口子）。
- **实体映射**：`settlement`（承接）；`service_assess`（读）。

#### P0 · R-STL-03 阶段结算与尾款结算
- **功能描述**：支持按阶段比例分期结算与尾款一次结清：结算单标记阶段号/比例/是否尾款，系统校验累计比例与余额。
- **AC**：① 结算方式：一次性 / 阶段（按比例，如 30%/40%/30%）/ 尾款（最后一次结清余款）；② 阶段比例在订单级维护（默认均分可改），Σ比例=100%；③ 尾款结算时校验：本单累计已结算+本次=订单应结总额；④ 阶段结算每期独立走审批与核销。
- **字段与状态机**：`settlement` **+ `settle_mode`(0一次性/1阶段/2尾款)、`+ phase_no`、`+ phase_ratio`、`+ is_final`(0/1)**。**新建枚举 `SettleMode`**。订单级阶段比例落 `purchase_order` **+ `phase_plan`（JSON，nullable）**。
- **实体映射**：`settlement`(+4)、`purchase_order`(+1)。

#### P0 · R-PAY-01 付款登记与状态回写
- **功能描述**：已结算（SETTLED）的结算单发起付款登记（付款金额/方式/日期/凭证），财务审核后线下付款，付款完成在系统**登记确认**回写状态。
- **AC**：① 付款申请经 `ApprovalGateway`（bizType=`PAYMENT`，财务审核），通过后状态=待付款确认；② 线下付款完成后由财务**手动登记确认**（上传付款凭证 `voucher_file`），置 `PAID` 并回写：结算单已付金额累计、全部付清→订单 `PAID`；③ 一结算单可多次付款（分期付），累计付款 ≤ 结算金额；④ 驳回（`REJECTED`）可修改重提；⑤ 一期不直连财务系统、不外发付款指令（经适配层属 P6）。
- **字段与状态机**：`payment`（已有 `settlement_id/pay_amount/pay_method/voucher_file/status/remark`）**+ `pay_no`、`+ pay_date`、`+ reviewed_by/reviewed_at`、`+ confirmed_by/confirmed_at`**。
  - 状态机（`PaymentStatus`）：`UNPAID（已申请待审/待付）→PAID（登记确认） / REJECTED（驳回→修改重提）`。
- **实体映射**：`payment`(+5)。

#### P0 · R-PAY-02 付款记录查询与对账单
- **功能描述**：付款台账（按供应商/结算单/日期/状态查询导出）；按供应商+期间生成对账单（应付=Σ结算、已付=Σ付款、差额）。
- **AC**：① 台账经数据权限过滤，支持导出；② 对账单按供应商×期间汇总：结算总额、付款总额、未付差额、单据明细清单，导出 Excel；③ 差额非零行可下钻到结算/付款明细；④ 对账口径为系统内口径（一期不与财务系统对账，见 Q3）。
- **实体映射**：查询视图，无新表。

### 4.3 成本管理（行 43–44）

#### P0 · R-CST-01 采购价格审核与价格库
- **功能描述**：异常价审核（报价/订单价触发规则或历史价偏离时进入审核），审核通过后价格沉淀**价格库**（历史价格，供比价/成本/价格治理取数）。
- **AC**：① 触发规则：价格超出 P1 `price_rule` 限价，或低于历史均价 X%（默认 20%，可配置）→ 标记异常待审核；② 审核（通过/驳回+意见）走独立审核动作（权限 `cost:price:audit`，**与商品录入权限独立**——需求评审 P0 口径）；③ 价格库 `price_history` 自动沉淀来源：报价采纳价、定标价、订单价，另支持手工补录；④ 价格库按 SKU+供应商+生效日期可查，P2 比价"历史比价"取数切换/兜底为价格库；⑤ 价格修正留痕（谁改、改前改后）。
- **字段与状态机**：**新建 `price_history`**：`sku_id, supplier_id, price, source(0报价/1定标/2订单/3手工), biz_type, biz_id, effective_date, audit_status(0待审/1通过/2驳回), audit_by/audit_at, remark`。**新建枚举 `PriceSource`**。
  - 与 P1 `price_rule` 关系（Q5 建议）：**两套分工**——`price_rule`=事前限价规则（建档/下单拦截），`price_history`=事后成交价沉淀（比价/审核/成本），不合一。
- **实体映射**：**新建** `price_history`；`price_rule`（P1，读）。

#### P1 · R-CST-02 成本核算与归集（按部门）
- **功能描述**：采购成本按部门归集核算：维度=部门×科目×月份，数据来自订单明细（数量×价格，基本单位口径），可下钻到订单。

- **实体映射**：聚合查询，无新表。

## 5. 预算占用 / 释放 / 核销 · 全生命周期规则表（核心交付）

> 口径：`used_amount = Σ占用 − Σ释放`（核销不改变总额，仅转移构成）；每行动作均写 `budget_occupy_log`；所有动作与业务状态变更**同事务**。

| # | 触发事件 | 动作 | 金额方向 | used_amount | 业务状态联动 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 申请提交（余额足） | **占用** | + | 增加 | `DRAFT→BUDGET_PENDING→PURCHASE_PENDING` | 事务内行锁 |
| 2 | 申请提交（余额不足） | **拦截+升级审批** | 0（暂不占用） | 不变 | `budget_status=2`，停 `BUDGET_PENDING`，bizType=`BUDGET` | 审批通过→按行 3；驳回→行 5 |
| 3 | 超预算审批通过 | 占用（超支占用） | + | 增加 | `BUDGET_PENDING→PURCHASE_PENDING` | 允许超支占用 |
| 4 | 超预算审批驳回 | 无（回草稿） | 0 | 不变 | `BUDGET_PENDING→REJECTED→DRAFT` | 修改后重新提交再校验 |
| 5 | 申请驳回 / 作废 | **释放** | − | 减少 | `REJECTED` / 作废 | 按该申请累计占用余额释放 |
| 6 | 订单生成 | **占用主体转移**（申请侧释放 − + 订单侧承接 +） | 0 | 净变化 = 订单金额 − 申请占用（预估价与成交价差所致；同链守恒） | 申请 `→PARTIAL_ORDER/FULL_ORDER`；订单 `CREATED` | log 两笔：申请侧 RELEASE + 订单侧 OCCUPY（biz_type=ORDER）；Σlog==used_amount 不变式不受影响 |
| 7 | 订单变更（减量） | **释放差额** | − | 减少 | `order_change` 生效 | 重跑校验 |
| 8 | 订单变更（增量） | **校验+占用差额** | + | 增加 | 同上；不足→拦截（同行 2 逻辑） | — |
| 9 | 订单取消 | **释放** | − | 减少 | `→CANCELLED` | 按本单占用余额释放 |
| 10 | 申请关闭（FULL_ORDER/作废） | 释放未转单余量 | − | 减少 | 申请收口 | 防止"假占用" |
| 11 | 结算审批通过（SETTLED） | **核销**（占用→核销） | 0 | 不变 | 订单 `→SETTLED`（全部结清） | log action=核销 |
| 12 | 付款登记确认（PAID） | 无预算动作 | 0 | 不变 | 订单 `→PAID` | 核销已在结算完成 |
| 13 | 月度调整（调增/调减） | **调整** | 0（改 amount） | 不变 | 调减校验 `amount≥used_amount` | log action=3，超阈值走 BUDGET 审批 |
| 14 | 每日对账任务 | 校准 | — | — | `Σlog(占用−释放) ≠ used_amount` → 告警 | 对齐架构 2.2-R2 |

> 锁与并发：行级锁（`budget_line FOR UPDATE`）+ Redis 锁 `budget:lock:{deptId}:{subjectId}` + `version` 乐观锁，三重保障（架构 2.2 基线，P2 下单事务方案沿用）。

## 10. 口径补丁 PB-01 · 付款状态口径（P3b D11 · 依据 PRD 裁决）

> 裁决日期：口径专项审计期间。依据 PRD v1.1：§6.11.1 L906"同一结算单可分批登记多笔实际付款，**累计已付和未付余额由付款记录自动计算**"；PAY-05(L917) 一个结算单对应多笔付款记录；PAY-06(L918)/§8(L1119) 付款状态=未付款/部分付款/已付清，**按累计实付金额计算**；数据模型(L1214-1215) `payment_task(payable_amount, paid_amount, status)` + `payment_record(amount, payment_date)`——状态挂在**结算/应付维度**，登记记录本身无状态。

**裁决：采口径 B（派生表达），"部分付款"属结算单维度，非付款单维度。**

1. **付款单（`payment`，一次登记一笔）**：整单确认即生效（`confirmPayment → PAID`），**不存在金额级部分确认**；`PaymentStatus` 删除 `PARTIAL(1)`，收敛为 `UNPAID(0 待登记) / PAID(1 已登记确认)`——线下付款后登记，登记即实付事实记录（PRD `payment_record` 无 status）。
2. **结算单（应付维度）**：新增派生付款进度 `paid_progress`（查询时按 Σ已确认付款计算，不落枚举硬存）：`paid=0 → 未付款`；`0<paid<payable → 部分付款`；`paid≥payable → 已付清`（累计登记受 BR-17 约束：Σ付款 ≤ 结算应付金额，超额拒绝登记）。`payable = 结算应付 − 已抵扣预付款`（PAY-07）。
3. **订单 PAID 判定**：派生展示字段，条件=该订单全部有效结算均"已付清"（Σ已确认付款 == Σ有效结算应付），维持审计条 20 口径；订单状态机仍不含 SETTLED/PAID（R5）。
4. **AC 补充**：① 同一结算单登记两笔付款（各 50%），付款进度依次呈现"部分付款→已付清"，两笔付款单均 PAID；② 第三笔付款超额被拒（BR-17）；③ 订单全部结算付清后 PAID 派生为真，任一结算未付清则非 PAID。
