# D16 无申请来源订单「需求来源」留痕 · 规格设计

> 关联台账：`docs/延期需求与占位登记.md` 行 27（D16）
> 溯源：主流程 docx《采购申请与采购订单关系》末段——"直接基于框架合同发起日常订单时可无采购申请，但**必须保留需求来源、预算归属和授权记录**"
> 配套：D14（授权留痕，已实现）、预算归属（早已 ✅）
> 设计原则：规格先行；复用 D9 Inquiry 的 `source_type`/`source_reason` 同构模式；接口契约不变（仅新增可选请求字段 `sourceReason`）

## 1. 背景与依据

主流程 docx 对 `applyId==null`（日常采购 / 基于框架合同直接发起、无采购申请）订单明确要求保留三项审计要素：

| 要素 | 现状 | 归属 |
|---|---|---|
| 预算归属 | ✅ 已落地 | 预算占用流水带 `subject_id`，来源=申请→定标→合同科目 fallback |
| 授权记录 | ✅ D14 已落地 | `authorized_by/name/time` + 超阈值升级 `DAILY_AUTH` |
| **需求来源** | ❌ 缺失 | 订单表无 `source_type`/`source_reason` 字段 |

D16 补齐最后一块，使 `applyId==null` 订单的审计三件套完整闭合。

## 2. 范围

- **仅 `applyId==null` 分支强制**：日常采购无申请来源，需求来源无法由采购申请间接表达，必须显式留痕。
- `applyId!=null`（标准 / 项目链路）：需求来源即采购申请，`apply_id` 已记录，本需求不重复强制；`source_type` 自动标 `APPLY`，`source_reason` 可选（允许前端附言）。

## 3. 数据模型

`purchase_order` 新增两列（位于 `auth_over_limit` 之后）：

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `source_type` | VARCHAR(20) | 否（自动推导） | 需求来源类型：`APPLY`=采购申请来源 / `OFFLINE`=无申请来源（日常采购/框架合同直发）。**由 `applyId` 推导，不接收客户端输入** |
| `source_reason` | VARCHAR(500) | `applyId==null` 时必填 | 需求来源说明（本次采购为何发起，供报表/审计追溯） |

> 与 D9 `Inquiry.source_type/source_reason` 同构（`OFFLINE` 必填 `source_reason`，BR-07）。

## 4. 逻辑（OrderServiceImpl.createOrder）

在 `applyId==null` 分支（D14 授权控制区块之后）插入：

```
String orderSourceType;
String orderSourceReason;
if (req.getApplyId() == null) {
    // 无申请来源订单必须填写需求来源说明
    if (req.getSourceReason() == null || req.getSourceReason().isBlank()) {
        throw new BizException(ResultCode.PARAM_ERROR, "无申请来源订单必须填写需求来源说明");
    }
    orderSourceType = "OFFLINE";
    orderSourceReason = req.getSourceReason().trim();
} else {
    orderSourceType = "APPLY";
    orderSourceReason = req.getSourceReason(); // 可选
}
```

`insertOrder(...)` 签名增加 `sourceType, sourceReason` 两参数，落库 `order.setSourceType/SourceReason(...)`。

## 5. 验收标准（AC）

- **AC1**：`applyId==null` 且 `sourceReason` 为空 → 抛 `PARAM_ERROR`（"无申请来源订单必须填写需求来源说明"）。
- **AC2**：`applyId==null` 且 `sourceReason` 有值 → 订单 `source_type=OFFLINE`、`source_reason`=输入值，订单正常创建。
- **AC3**：`applyId!=null` → `source_type=APPLY`，`source_reason` 可为空，不受强制校验影响。
- **AC4**：D14 授权留痕 + 预算归属 + D16 需求来源三件套在 `applyId==null` 订单上并存，审计闭环。

## 6. 风险与约定

- **R1（前端）**：前端需在"日常采购/无申请"下单表单补「需求来源说明」输入项（原型对齐，独立前端批）。后端先落地字段 + 校验，接口契约不变（仅 `OrderCreateReqVO` 新增可选 `sourceReason`）。
- **R2（迁移）**：新建库经 `schema.sql` 自动含本批列；存量库执行 `scripts/sql/d16_schema.sql`（幂等，基于 `information_schema` 判重）。
- **契约稳定**：仅新增字段/可选请求项，不改动既有状态机、接口、枚举——符合台账"临时方案只换实现不改契约"铁律。
