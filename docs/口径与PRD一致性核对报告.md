## §2 逐条核对表（28 条）

> 格式：决策 → PRD 原文（章节+行号）→ 结论。

### P1 主数据

**1. budget_line 含项目+部门双维度，period 0/1-12（A1）**
→ PRD §0.2(L49)"额度控制按部门和预算科目；项目保留为业务归属和统计维度"；§6.4.1(L608-609)"项目不参与预算额度控制，额度控制键为部门+月份+预算科目"；L1197 `budget`=year+month+department+subject+amount+used_amount（每月一条，无年度行）。
→ **🔴 违背**。项目维度不应参与额度（可保留为统计冗余）；period=0 年度额度行不符合 PRD——年度是 12 个月的聚合展示，硬控按月。P3 修正了"月度硬控"但**未清掉 period=0 年度行与项目参与额度**，修正不完整。

**2. 资质审核走 ApprovalGateway（A2）**
→ PRD §6.16(L1066) 资质审批属审批单据中心七类之一，"单条或批量通过、驳回；驳回原因必填"；§6.3.4(L586) 批量审核。
→ **🟢 方向一致**（走 Gateway 正确）；**🟡 缺批量审核能力**；资质模型缺 version/有效状态独立/change_type/history（§6.3.2 L559-564、L1190-1191）。

**3. 供应商-商品绑定优选非强制（A3）**
→ PRD L553 绑定/货号/供货价"代码保留，入口隐藏，不作为当前已开放功能"。
→ **🟡 超前实现**。方向无害（供应商箱规差异维护在供应商采购信息 L490），但一期验收范围与 PRD 不符，需在验收说明中标注；"优选带入"口径 PRD 无定义（自行补）。

**4. 单位换算版本化+快照三字段**
→ PM-07(L502)"申请、询价、订单、验收和同步保存快照"；L518"修改换算规则只影响后续新单据"；BR-02/BR-21。
→ **🟢 一致**。版本化/effective_from 为增强（PRD 数据模型 L1186 无 version 字段，不冲突）。注意快照对象含"同步"（P6）与"询价"，我们落了"定标"——覆盖面等价偏全。

### P2 主链路

**5. P2 只做标准链路，日常/框架+线下补录放 P2b**
→ PRD 主链（§5.1）本身即包含：无申请独立寻源（L341、BR-07）、线下直接定标登记（L682）、框架合同日常订单可不关联申请（L656、L747）。原型"定标管理"页有**线下定标登记**入口（实测）。
→ **🟡 顺序安排可接受**（P2b 计划已在延期表 D1/D2 登记），但注意：线下定标登记在原型中属主链页面功能，P2b 范围需包含"无申请询价+寻源原因"，不止框架免比价。

**6. 审批层级：申请两级/定标一级/合同一级+金额阈值升级**
→ PRD §16.1(L1478)"采购申请审批链和超预算审批流程的具体节点"明确列为开发前待确认；§6.16 七类审批。
→ **🟢 基本一致**（层级 PRD 留白）；**🟡 合同金额阈值升级为我们自行补的参数**。

**7. P2 预算软校验**
→ PRD L629-633"预算不足时**软阻断**，单据保留并在采购申请中**进入预算审批**；通过前不能进入采购审批，也不能继续定标或下单"（L429/BR-05/PR-05/06）。
→ **🔴 阶段性行为违背**：P2 实现的"仅提示不拦截、流转继续"不符合 PRD"软阻断=转预算审批"。P3 已升级为拦截+升级审批（正确），此项作为过渡态登记，需在 P2b 回归核对照 PR-05/06/07 全链（预算审批未通过不能进采购审批/定标/下单）。

**8. 比价最低价中标+异常价复核；定标按 SKU 拆多供应商**
→ §6.6.4(L717-721) 比价维度=总价、单价、**税率、运费、交期**和资格；人工"选择并确认中标供应商"（单数）；L1201 awarded_supplier_id 单数；原型定标供应商列单个。
→ **🔴 拆标违背**（PRD 一询价单一定标供应商）；**🟡 最低价中标为辅助规则自行补**（PRD 为人工择优，不冲突）；**🟡 报价缺税率/运费/交期字段**，比价维度不完整。

**9. 履约调整 5% 免审；变更仅未到货+重跑三重校验**
→ §6.7.3(L772-778)："生产版本可配置是否启用审批"；履约调整进入审批单据中心（L776）；全部完成才不可调整（L774、AC-12B）；调减释放合同+预算占用；**超付预付款退款/转余额/抵扣**（L777、BR-27）。
→ **🔴 违背**：免审阈值与 PRD"进审批中心"冲突；"仅未到货"比 PRD 严（PRD 允许部分到货调整）；缺超付预付款处理与"已结算部分不得调整"。

**10. 库存只做到货验收入库台账**
→ §0.2(L51)、§6.8、BR-13/14、非目标(L142)。
→ **🟢 一致**。

**11. 询价发布剔除式准入**
→ RFQ-03(L691)"只能选择合作中、未拉黑、资质有效的供应商"——选择时过滤，非事后剔除；"供应商范围创建时**选填**"；已有报价供应商不能移除。
→ **🟡 实现方式偏差**（结果等价但交互不同；"剔空才报错"非 PRD 口径）；供应商范围应选填（我们要求≥1 家才能发布，PRD 要求发布需产品明细完整）。

**12. 报价导入全有或全无+错误 Sheet；批次失效按供应商**
→ L712"格式错误不允许产生部分脏数据，必须返回明确行级错误"（🟢）；RFQ-09 校验含税率/运费/交期（🟡 缺字段）；L702 供应商必须在询价范围内，整行拒绝（🟢）；RFQ-10 版本保留（🟢）。
→ **🟢 主体一致，🟡 缺税率/运费/交期**。

### 全局/平台

**23. SUPER_ADMIN+hasAnyPerm 粗门禁**
→ §2.2(L174)"正式系统必须实现后端权限校验，前端隐藏按钮不能作为安全边界"；§6.14 角色权限。
→ **🟢 方向一致**（阶段一粗门禁过渡已声明，阶段二细化 `module:action` 计划不变）。

**24. 审批统一走 ApprovalGateway（7 bizType）**
→ §6.16 七类：采购申请/预算调整/定标/合同/履约调整/结算/**资质**。
→ **🟢 对齐**；**🟡 PAYMENT 多余**（见 R6），`BUDGET` 对应"预算调整审批"（L1061 来源含手工预算调整 🟢）。

**25. 枚举 name 字符串契约、Long→String 序列化**
→ PRD 无此规定（技术实现层）。
→ **🟢 不适用/无冲突**。

**26. 一期不直连财务**
→ §0.2(L50)、§1.5(L144)、§5.2(L420)。
→ **🟢 一致**。

**27. 报表中心阻塞（业务需求未提供）**
→ PRD §6.12(L928-966) 有**完整**报表需求：采购统计（汇总/结构/明细两级菜单）、预算执行、成本报表（成本结构分析）、履约报表、同步报表，含指标口径与页面要求，标注"生产目标口径"（REPORT_CENTER_ENABLED=false 仅指原型入口隐藏）。
→ **🔴 判断错误**：非真阻塞，需求已在 PRD。建议解除阻塞、单独排期（成本归集维度需补：申请部门/品类/项目/供应商/月份，L936——当前 P3 只做部门×科目×月，不足）。

**28. 原型对齐（主题+功能流）**
→ 见 §5 实测结论：菜单/页面结构与 PRD §9.1 一致；样式已对齐前提下，**功能流有三处需回对**：定标单供应商（R2）、线下定标登记入口（R9）、月度预算台账（R1）。

## §4 PRD 待商榷项（不盲从，单列）

| # | 事项 | 说明与建议 |
|---|---|---|
| P-1 | 定标单供应商 vs 拆标现实 | 大宗多品类询价实务常按 SKU 拆给多家。PRD 单中标供应商+`awarded_supplier_id` 单数是明确口径，建议**先按 PRD 实现**；若业务确认需要拆标，走 PRD 变更（rfq_award 支持多中标行）而非私改 |
| P-2 | 阶段结算"金额自行填写" vs 比例配置 | PRD L869 业务人员自行填写金额更灵活，建议采纳 PRD（比例仅作默认建议值） |
| P-3 | 月度调整一律审批 | 保守但可审计，符合 L635 与 budget_adjustment 状态机，建议遵从；如业务要调增直通，列变更申请 |
| P-4 | 预算导入模板仅"按年/按月"两种、方案=均摊/季度比例/手工 | 我们 P1 A1 设计未覆盖"季度比例"方案，需补齐模板能力（AC-01/01A） |
| P-5 | 报价含税单价口径 | PRD 全链按"含税单价×数量"，税率参与比价；我们价格字段未区分含税/税率，需统一（BR-23 两位小数） |
| P-6 | 供应商资格"最新资质审核状态为已通过" | 资质过期后供应商整体状态如何自动联动（暂停合作?）PRD 未细说，仅说限制参与；建议保持我们 coop_status 独立设计并登记 |
| P-7 | 超收/计重误差 | PRD L793/L1480 明确留白待业务确认（超收规则、净重/毛重），建议随 P2b 一并向业务收集 |
| P-8 | PRD 0.5/L86 "工作台/系统设置/合同类型/付款条款"入口隐藏 | 团队部分实现（如预警）属提前开放，需在验收范围说明中登记，避免"入口错位"事故重演 |
