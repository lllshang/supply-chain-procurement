## 3. 权限与安全边界（❌ 未满足硬约束）

### 3.1 后端是否强制权限？——「仅认证，未授权」

| 事实 | 证据 |
|---|---|
| 无方法级鉴权 | 全仓 `grep -rn "PreAuthorize\|EnableMethodSecurity\|@Secured\|hasAuthority\|hasRole"` → **无任何匹配** |
| SecurityConfig 只到 `authenticated()` | `backend/.../config/SecurityConfig.java:64-66`：`urls.forEach(permitAll); auth.anyRequest().authenticated();` |
| 所有业务写接口无保护 | `BaseController.java:50-52` `@PostMapping → service.save()`、`:55-58` `@PutMapping → updateById`、`:61-63` `@DeleteMapping → removeById`；24 个 Controller 全部继承 BaseController |
| 设计明确要求后端强制 | `docs/技术评审与架构设计.md:73`「**权限校验必须后端做**……前端按钮隐藏仅为 UX，非安全边界」；`:126`「后端 `@PreAuthorize`/AOP 强制校验」 |

### 3.2 越权 PoC（运行时实证，非推测）

造一个 **0 角色 / 0 权限** 用户 `qa_noauth`（复用 admin 的 BCrypt，`sys_user_role` 无记录），登录后调用管理接口：

```
[登录] qa_noauth（0 角色 / 0 权限）-> HTTP 200 code=0
      user: {"id":999,"username":"qa_noauth","deptId":1,"roles":[],"perms":[]}

[越权读] 同一 token 访问：
   GET /api/v1/org/users/page        -> HTTP 200 code=0     ← 用户列表
   GET /api/v1/rbac/roles/page       -> HTTP 200 code=0     ← 角色列表
   GET /api/v1/rbac/menus/list       -> HTTP 200 code=0
   GET /api/v1/org/depts/list        -> HTTP 200 code=0
   GET /api/v1/contracts/page        -> HTTP 200 code=0
   GET /api/v1/budgets/page          -> HTTP 200 code=0

[越权写] DELETE /api/v1/contracts/999999 -> HTTP 200 {"code":0,"message":"成功","data":false}
```

> 结论：**任何登录用户可读全部管理数据、可执行任意写操作**。「前端隐藏 ≠ 安全边界」这条需求硬约束**未落地**。
> 补充：`/api/v1/menu` 对无角色用户返回 `[]`（菜单按 RBAC 收敛是好的），说明**菜单是授权的、接口不是**——正是最典型的“假安全”。

### 3.3 数据权限（部门隔离）

| 事实 | 证据 | 运行后果 |
|---|---|---|
| 拦截器恒返回 null | `permission/DataPermissionInterceptor.java:17`：`DataPermissionHandler handler = (where, mappedStatementId) -> null;` | 任何查询都不追加 `AND dept_id IN (...)` |

### 3.4 认证入口与响应体契约（⚠ 不一致）

| 场景 | 实测 | 期望（设计/前端约定） |

### 5.1 ❌ P0-1：按交付配置后端**无法启动**

**首跑（完全按仓库默认配置）结果：**
```
Caused by: java.sql.SQLException: Unsupported character encoding 'utf8mb4'
    at com.mysql.cj.jdbc.ConnectionImpl.<init>
Caused by: java.io.UnsupportedEncodingException: utf8mb4

Error creating bean with name 'dataSourceScriptDatabaseInitializer' ... Failed to execute database script
Exception encountered during context initialization - cancelling refresh attempt
→ 进程退出，Tomcat 未启动
```
**根因（3 处同一错误）**：
- `backend/src/main/resources/application.yml:28`
- `backend/src/main/resources/application-dev.yml:7`
- `docker-compose.yml:66`（`SPRING_DATASOURCE_URL`）

均为 `...?useUnicode=true&characterEncoding=utf8mb4&...`。MySQL 驱动 `characterEncoding` 需要 **Java 字符集名（`UTF-8`）**，不接受 `utf8mb4`。

**对照实验**：仅将 URL 改为 `characterEncoding=UTF-8`（**不改任何源码，仅环境变量覆盖**）→
```
Tomcat started on port 8080 (http)
Started SupplyChainApplication in 6.06 seconds
```
> 即：**编译通过 ≠ 可运行**。工程师自报“可启动”未经运行时验证，阶段一「可运行底座」目标**未达成**。

## 7. 遗留风险

1. **上线阻断**：P0-1 不修则服务起不来；P0-2 不修则超管权限不完整（且被前端兜底掩盖）。
2. **安全**：P0-3（授权缺失）+ P1-4（数据权限缺失）叠加 → **任一登录用户可跨部门读/改全部业务数据**。阶段二一旦接入真实业务数据，风险即时放大。
3. **编排链路**：`docker compose up` 全栈未端到端验证；结合 P2-9，容器化后端存在确定性启动失败。
4. **回归防护**：P3-13 零测试 + P2-8 wrapper 缺失 → 阶段二多人并行开发时回归风险高、构建环境不一致（8.7 vs 9.x）。
5. **共享环境**：compose 固定占用 3306/6379/9000/80/8080/8081，在多人共用主机上易冲突（本次即撞到 6379）。
6. **配置漂移**：P2-12 双份 SQL 已漂移，后续必再出错。

## 8. 修复建议（给工程师的优先级顺序）

1. **P0-1**：三处 `characterEncoding=utf8mb4` → `characterEncoding=UTF-8`（或改用 `connectionCollation=utf8mb4_0900_ai_ci`），并在 CI 增加“启动冒烟”步骤（起容器→探活 `/actuator/health`）。
2. **P0-2**：`data.sql:51-53` 与 `scripts/sql/data.sql:15,38,51-53` 的 `role_id/id` 一律改回 `1`；两处 SQL 用同一份（后端 classpath 为唯一源，`scripts/sql` 改软链或删除）；补一条启动自检断言「超管菜单数 = 12」。
3. **P0-3 / P1-4**：启用 `@EnableMethodSecurity` 并在写接口加 `@PreAuthorize("hasPerm('...')")`；`DataPermissionInterceptor` 按 `DataScope` 实现真实 `dept_id` 注入（含本部门/子树/全部）；两者均补越权回归用例。
4. **P1-5**：写接口由后端强制填充 `deptId`（取 `UserContext.getCurrentDeptId()`）、`applyNo`（`IdGenerator`）、`applicantId/status`，禁止前端直传落库。
5. **P1-6 / P1-7**：`GlobalExceptionHandler` 增加 `NoResourceFoundException/NoHandlerFoundException` → 404 分支；`SecurityConfig` 配置 `AuthenticationEntryPoint`/`AccessDeniedHandler` 输出统一 `{code:2001/2004}` 体。
6. **P2-8**：提交 `backend/gradlew` 与 `gradle/wrapper/gradle-wrapper.jar`（后者从 `.gitignore` 移除）；统一锁定 Gradle 8.7。
7. **P2-9 / P2-10**：`docker-compose.yml:70` 改 `APP_MINIO_ENDPOINT`；`MinioConfig.fileStorage` 改懒初始化或容错（MinIO 不可用不阻断启动）。
