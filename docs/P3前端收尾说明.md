## 二、PaymentIndex R6 适配审计结论

**结论：零改动。** `grep` 全量核对 `frontend/src`：

1. **payment 域无已删端点残留**。payment 域文件（`api/settlement.js` payment 段、`views/settlement/PaymentIndex.vue`）中无 `/submit`、无审批类（approve/reject）调用。全库出现的 `submit*` 均为其他域合法端点：`submitSettlement`（结算域 `/settlements/{id}/submit`，合法）、`submitApply`/`submitAward`/`submitContract`/`submitAdjust`（P2 域，合法）。
2. **登记确认走 R6 口径**：`PaymentIndex.vue` 引用 `confirmPayment`（`POST /api/v1/payments/{id}/confirm`，免审批，凭证+日期 → PAID），导入于 L121-123、调用于 L201。
3. **枚举口径一致**：`constants/enums.js` 的 `paymentStatus` 仅剩 `UNPAID/PAID` 两态（REJECTED 已随 R6 删除）；`approvalBizType` 无 `PAYMENT`（付款免审批，注释已注明）。
   **口径澄清**：`settlementPayStatus`（UNPAID/PARTIAL/PAID 三态）是另一张 map——PB-01 结算单**派生**付款状态，后端 `SettlementServiceImpl` 实际产出 `"PARTIAL"`，`SettlementIndex.vue` 列表/详情两处绑定，非死数据，勿与 `paymentStatus`（付款单状态机，两态）混淆。

**逐端点对照表**（`api/settlement.js` payment 段 ↔ `PaymentController.java`）：

## 三、对账单页对 R-PAY-02 的覆盖

- **AC①②（按供应商/期间出对账单，汇总+明细）**：筛选区（供应商ID 必填 + from/to 期间）→ `getStatement`；汇总 `el-descriptions` 展示应付/已付/差额（后端字段 `totalPayable/totalPaid/balance` 为准，保留 `??` 兼容读法）；明细 `el-table` 日期/单号/金额/备注。
- **AC③（差额非零可下钻）**：实现方案为**明细行增加「来源类型」可读列**——`StatementVO.Row.direction`（`SETTLEMENT/PAYMENT`）映射为「结算单/付款单」，与「来源单据号」列（`docNo`：JS-… 结算单 / FK-… 付款单）配合，差额可逐行追溯到具体结算/付款单据，点击成本为零、无需额外请求。
- **导出**：`exportStatement` blob + `saveBlob`（复用 `@/api/purchase2`，与 PaymentIndex 对话框同模式）。

## 四、价格库页对 R-CST-01 的覆盖

- **待审列表**：`getPricePending()` 全量列表，列取自 `PriceHistory` 实体（skuId/supplierId/price/source/bizType+bizId 来源单据/effectiveDate/auditStatus/remark/createdAt）；仅 `auditStatus === 'PENDING'` 行显示「通过/驳回」。
- **通过**：直接 `auditPrice(id, { approved: true, remark })` 落库，ElMessage 反馈 + 刷新。
- **驳回**：弹窗**必填 remark**（空值前端拦截）→ `auditPrice(id, { approved: false, remark })`。
- **近期通过价参考面板**：输入 SKU ID（limit 可调，默认 5）→ `getPriceRecent` 小表，供审核时比价参考。
- **枚举**：按后端 `PriceAuditStatus`（PENDING/APPROVED/REJECTED）与 `PriceSource`（QUOTATION/AWARD/ORDER/MANUAL）枚举名补充 STRING_ENUMS（#33 name 契约），状态/来源用现有 `StatusTag` 渲染。

## 五、设计裁量说明

1. **价格库菜单归属**：挂入「商品库管理」（parentId=2，child id=207，路径 `/catalog/price-audit`）。理由：价格库（price_history，事后成交价沉淀）与既有「价格规则」（price_rule，事前限价，204）是同一价格域的两套分工（实体注释亦如此表述），紧邻放置最贴切；12 个根菜单中无「成本管理」，为两个按钮级页面新增一级菜单反而打破现有信息架构。
2. **种子幂等方式**：沿用 `db/data.sql` 现有模式——菜单用 `INSERT IGNORE`（主键冲突即跳过），SUPER_ADMIN 授权同样 `INSERT IGNORE`（新授权行 id 取现最大 47 之后的 48/49，不与既有冲突）；`application.yml` 的 `spring.sql.init.mode=always` 每次启动执行，已初始化的 3307 库重复执行不报错。已 grep 确认 `scripts/sql/` 下均为 schema 迁移文件、无双份菜单种子，唯一种子源即 `db/data.sql`。
3. **对账单页不接分页**：对账单为报表型单次查询（后端 statement 返回全量 rows），非分页列表，不适用 `usePagination` 纪律；价格库待审列表同理（后端返回 `List` 非分页）。
