## 1. 代码级现状盘点（实测，非推断）

### 前端屏幕（`frontend/src/views`）
- **P2 主链路（均已是真实视图）**：`purchase/ApplyIndex`(采购申请)、`InquiryIndex`(询价)、`QuotationIndex`(报价)、`AwardIndex`(定标)、`order/OrderIndex`(订单)、`ArrivalIndex`(到货验收)、`AssessIndex`(服务考核)、`AdjustIndex`(履约调整)、`contract/ContractIndex`(合同)。
- **P3 主数据（真实视图 + API）**：`budget/BudgetSubject`、`BudgetProject`、`BudgetLedger`、`BudgetImport`；`api/budget.js` 仅暴露 科目 / 项目 / 导入 / 台账 四类。
- **P3 事务屏缺口（关键）**：
  - 结算与付款路由 `settlement` 指向 `ModulePlaceholder.vue`（**占位符，未建**，`router/index.js:53`）；
  - **付款（payment）路由根本不存在**；
  - 月度预算调整 UI 前端未检索到（属 P3 财务台账侧，待确认）。
- **S9 硬缺口**：`budgetSubjectId` 在 `frontend/src` 全仓**零引用** —— 申请表单无预算科目选择器。而后端 `PurchaseApplyServiceImpl.submit()` 已强制 `budgetSubjectId != null`（QA2-01），**意味着当前前端提交申请会被后端必填校验直接拦截**。

### 后端控制器（`backend/src/main/java/com/dzgylxt/controller`）
P3 事务端点**已齐**：`SettlementController`、`PaymentController`、`BudgetController`、`BudgetExecutionController`、`FulfillmentAdjustController`、`order/*`、`purchase/AwardController` 等。
**结论：后端能力具备，缺口全在前端接线 + P3 事务屏建设。**

## 3. 收尾任务拆解（按工作流分组：前端为主，后端基本就绪）

### A. 硬阻塞修复（必须最先做，否则 P2 主链路跑不通）
- **A1【S9·前端】** 采购申请表单增加"预算科目"选择器（调 `listBudgetSubjects`），提交 payload 带 `budgetSubjectId`。验收：提交走通、后端不再抛"未填写预算科目"。
- **A2【R7·前端+后端】** `AwardIndex` 定标提交/确认接入 `checkOnly`，超支走 `BUDGET` 审批分支；P2 设计 §2.4 补联动点说明。验收：定标确认触发预算再校验、跨科目互吃被拦。

### B. P3 事务屏建设（当前最大缺口）
- **B1【结算屏】** 新建 `views/settlement/SettlementIndex.vue` + `api/settlement.js`，对接 `SettlementController`：验收取数（CP-3）、提交、审批回调触发 `writeOff`（CP-7）。替换 `ModulePlaceholder`。
- **B2【付款屏】** 新建 `views/settlement/PaymentIndex.vue` + `api/payment.js`，对接 `PaymentController.confirmPayment`；付款状态 UNPAID→PARTIAL→PAID（CP-8，R5）。
- **B3【月度调整 UI】** 确认/新建预算月度调整入口，对接 `BudgetExecutionController.adjustAmount`（CP-9，R8）。

### C. P2 文档/契约修订（与设计层偏差对齐）
- **C1【R3】** 修订 P2 设计 §2.8/§3：取消 5% 免审、一律 `FULFILLMENT_ADJUST` 审批；放开部分到货可调整；补超付预付款处理（退款/转余额/抵扣）。
- **C2【R5】** P2 订单状态机/VO 去除 SETTLED/PAID 流转，改 `settleProgress`/`paidProgress` 派生；前端订单列表/详情同步。
- **C3【R9】** 登记为 P2b 首批：询价补来源类型 + `source_reason`，线下定标登记入口；**显式定义无申请定标的预算占用入口**，否则 CP-11 断裂。
- **C4【R2】** 文档补一句"已按单中标/按 inquiry 唯一落地（commit dfc62fc）"对齐说明，关闭留白。

### D. 回归登记项（已知缺口，不阻塞当期，入台账）
- S1 `price_rule` 弱化参考价提示；S2 绑定入口隐藏标注；S3 合同阈值升级登记；S4 报价补税率/运费/交期；S5 资质批量审核+version；S6 询价准入方式；S7 已对齐登记；S8/#13 合同价格清单第四重校验（相邻 closure）；S10 到货拒收退货/超收计重；S11 服务扣款多条明细取数（影响 CP-3 金额）；S12 SKU 标准价/箱规。
