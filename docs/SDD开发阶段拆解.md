# 供应链采购协同中台 · SDD 开发阶段拆解

> 目的：按 Spec-Driven Development 流程把开发任务拆成阶段，明确每阶段范围、交付物与依赖，并厘清外部依赖（统一认证 / 审批中心 / 外部系统）是否阻塞业务开发。
> 进度跟踪：飞书表「供应链系统进度表」(sheet 6ad641) 已新增 **K=开发完成时间、L=测试完成时间** 两列。

## 1. 阶段一已埋的三个抽象接缝（决定能否并行开发）

阶段一（地基）刻意把三个"不确定的外部依赖"抽象成**接口 + 本地桩**，使业务模块只依赖接口、不依赖真实实现：

| 外部依赖 | 接口（契约） | 当前本地桩 | 业务侧用法 | 真实接入阶段 |
|---|---|---|---|---|
| 统一认证 | `AuthProvider` | `LocalAuthProvider` | 业务按接口取当前用户/部门，不碰真实 SSO | P5 |
| 审批中心 | `ApprovalGateway` | `LocalApprovalGateway`（仅落库） | 触发审批只调 `gateway.create()`，本地桩直接"模拟通过" | P4 |
| 外部系统（二消等） | `Adapter` | `NoopAdapter` + `OutboxEvent` | 业务只写 Outbox 事件，Noop 仅打日志 | P6 |

**结论：统一认证、审批中心、外部系统三者都不是业务开发的硬阻塞点**，可全程用本地桩把 P1–P3 跑通，再在 P4/P5/P6 分别替换实现。

## 2. 阶段划分（对齐进度表功能行）

每阶段遵循 SDD：先出该组功能的 Spec（字段/校验/状态机/验收标准）→ Design（实体/服务契约/接口）→ Tasks（实现清单），再编码与测试。

| 阶段 | 范围（进度表行） | 做什么 | 依赖 |
|---|---|---|---|
| P0 地基 | 3 | 工程脚手架、认证与会话骨架、RBAC 模型、异常/日志/审计底座、CI/CD、Docker（**已完成，QA 通过**） | — |
| P1 主数据/基础配置 | 7–15 | 产品库 SPU/SKU·多单位·产品配置；供应商档案/配置/资质；预算科目与年度预算导入 | 无 |
| P2 采购主链路 MVP | 18–29 | 申请→询价→报价→定标→合同→订单→到货验收，走本地桩端到端跑通 | P1 |
| P3 预算硬控·结算·付款 | 37–44 | 预算占用/释放、超预算审批联动、结算、付款、成本核算 | P1+P2 |
| P4 审批中心接入 | 30–36 | 用真实实现替换 `LocalApprovalGateway`（回调/幂等/重试/留痕） | 接缝已就位 |
| P5 统一认证接入 | 4 | 用真实 SSO 替换 `LocalAuthProvider`，权限模型对齐 | 接缝已就位 |

| P7 报表·H5·上线 | 45–56 | 报表中心、供应商 H5、单元/接口/模块测试、UAT、非功能测试、试点/上线 | P2–P6 |

## 3. 各阶段交付要点

- **P1 主数据**：纯 CRUD + 业务规则，无任何外部依赖，可立即开工。重点：SPU/SKU 多规格、多单位换算快照、供应商分级与黑名单、资质有效期/预警、预算科目与年度预算导入。
- **P2 主链路**：标准链路端到端。所有"触发审批"走 `ApprovalGateway`，所有"外部同步"写 `OutboxEvent`。
- **P3 预算硬控**：采购申请提交即占用预算、合同/订单金额回写、超预算走审批网关；结算/付款独立成账。
- **P4–P6 接入**：仅替换接缝实现，业务代码基本不动；预留联调时间处理回调协议/幂等/超时/权限映射差异。

## 4. 阻塞点分析

- **非阻塞（可并行往下做）**：统一认证 / 审批中心 / 外部系统 —— 见第 1 节接缝设计。
- **唯一硬依赖**：业务模块间先后顺序（合同依赖定标、订单依赖合同、结算依赖验收、预算占用依赖预算模块）—— 用 P1→P2→P3 顺序 + 本地数据自洽解决，不卡外部。
- **真阻塞**：报表中心（行 45–47）需求未定（表内注明"等待业务方提供需求"），需业务方确认后再排期。

⚠️ 风险提示：本地桩跑通 ≠ 真实对接无坑。P4/P5/P6 换真实实现时回调协议、幂等、超时、权限映射可能与本地假设不一致，需预留联调时间。
