## 缺陷清单

### #1（P1）近期通过价面板对真实雪花 SKU ID 100% 查不到数据（Round 2 已修复，见 R2-1）
- **位置**：`frontend/src/views/cost/PriceAuditIndex.vue:161-162`（`loadRecent`）
- **根因**：`const skuId = Number(recentSkuId.value)` —— 19 位雪花 ID 超出 `Number.MAX_SAFE_INTEGER`，精度丢失。实测 `Number('2102245024849907713')` → `2102245024849907700`。后端按错误 skuId 查询返回空数组，前端于是提示「该 SKU 暂无近期通过价」。
- **影响**：当前库全部真实 SKU ID 均为 19 位（2102245024…），**该面板对任何真实数据都不可用**，R-CST-01「审核时比价参考」失去数据支撑；API 本身（`/price-histories/recent`）功能正常，纯前端缺陷。
- **复现**：登录 → 商品库管理 › 价格库审核 → 近期通过价面板输入真实 SKU ID（如 `2102245024849907713`，DB 有 17 条通过价）→ 查询 → 提示「暂无近期通过价」；同参数 curl 直接调 API 返回 17 条。
- **修复建议**：SKU ID 保持字符串直接作为 query 参数传后端（`request.get('/…/recent', { params: { skuId: recentSkuId.value.trim(), limit } })`），仅用正则校验纯数字格式，不做 `Number()` 转换。

### #2（P2）异常价阈值三处口径不一致（前端文案 20% ≠ 后端实现 30%）（Round 2 已修复，见 R2-2）
- **位置**：`frontend/src/views/cost/PriceAuditIndex.vue:6`（页面 tip 硬编码「低于历史均价 20%」）↔ `backend/.../PriceHistoryServiceImpl.java:33`（`app.price.abnormal-percent:30`，yml 未覆盖，实际生效 30%）↔ `docs/P3预算结算规格设计.md:131`（AC①「默认 20%，可配置」）。
- **影响**：审核人员按页面文案理解的触发阈值与实际相差 10pct；误导审核判断。后端 30% 为既有行为（73ef3ce，非本次三提交引入），但新页面文案放大了不一致。
- **修复建议**：统一为 20%（改 yml 配置）或 30%（改设计+前端文案），三处取齐。

### #3（P2）新页面写按钮未挂 v-permission，且审核权限未按设计独立绑定（Round 2 已修复，见 R2-3）

- **伴生**：后端 `PriceHistoryController` 三个端点均为 `@authz.hasAnyPerm`（任意权限即可调，PriceHistoryController.java:32/39/47），未绑定 `catalog:price:audit`；设计 R-CST-01 AC② 要求审核权限「与商品录入权限独立」。当前独立权限仅靠菜单可见性约束，持任意其他权限的低权限用户绕过前端可直接 POST 审核成功（本报告未利用此路径做破坏性验证，仅静态判定）。
