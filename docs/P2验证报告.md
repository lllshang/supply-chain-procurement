### P1（功能缺陷，须修）
21. **【后端·P0 功能】报价模板以数值类型写 19 位雪花 ID → Excel double 精度丢失 → 按模板导入必然失败** — `QuotationServiceImpl.exportTemplate`（SKU/供应商 ID 列写数值单元格）+ 导入侧数值解析。

    建议：模板 ID 列以文本格式写入（`DataFormat` "@" + `setCellValue(String)`），导入侧兼容数值/文本（`DataFormatter` 或字符串读取）。
22. **【后端·P0 口径】合同金额校验按定标单**总额**（含其他供应商份额）** — `ContractServiceImpl.java:85-93`（`Σ award_item` 无 `supplier_id` 过滤）。
    复现：定标按 SKU 拆 2 家（GOOD 12×88、GOOD2 12×90，总额 25632）→ 登记 GOOD 合同 `amount=12672`（其真实份额）→ **4000**「合同金额必须等于 Σ 定标明细金额：25632.00」；GOOD2 合同 `12960` 同样被拒，被迫登记 25632 → 两张合同总敞口 51264 ≫ 定标 25632，额度守恒失真且 GOOD 可用额度含 GOOD2 货值（下单越份额"合法"）。
    违反规格 R-AWD-01 AC②「可拆分给多家」+ R-CON-01 AC①「合同金额 = Σ来源定标明细金额」（应按**该供应商**明细 Σ）。

### P2（语义口径 / 健壮性，建议修）
23. **报价批次失效为询价全局而非按供应商** — `QuotationServiceImpl.java:196-200`（`.eq("inquiry_id")` 无 `.eq("supplier_id")`）。
    复现：GOOD 报 88（batch -05 有效）→ GOOD2 导入 90（batch -06）→ **GOOD 的 -05 被置 invalid=1**。违反 R-INQ-02 AC⑤「**同一供应商**重复导入生成新批次，旧批次置失效」；后果：多家有效报价无法共存，比价退化为"最后导入的一家"（本轮 comparison 实测仅剩 1 家有效），削弱比价竞争与定标择优。
24. **错误行导入"部分落库"** — 复现：3 行（价格 -5 / 价格 0 / 合法 88）导入 → `{"total":3,"success":1,"fail":2,"errors":[...]}` 且**合法行已入库**（batch -05 落 1 行）。规格 AC④「错误行收集为错误 Sheet…**全部通过才落库**」。现行为"逐行校验、合格行照落"，与 AC 不符（另：错误仅以 JSON 返回，无"错误 Sheet"文件）。建议：整批事务化，存在错误行则整体拒绝。
