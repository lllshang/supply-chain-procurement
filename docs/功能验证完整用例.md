### 3.4 采购主链路（`/purchase/*`）

#### UC-PUR-01 采购申请 → 审批 → 关联合同下单（日常/框架链路 D1）
| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 「采购申请」`/purchase/apply` 新建日常采购申请，填物料/数量/需求时间/用途 | 保存为草稿 |
| 2 | 提交审批 | 走部门负责人→预算校验→采购部环节；可驳回 |
| 3 | 审批通过后，基于申请 + **履行中合同** 下单 | 订单生成；**订单必须挂履行中合同**（L743 硬规则） |

**核对点**：`purchase_apply` 状态流转正确；订单 `contract_id` 非空且合同为履行中。

#### UC-PUR-02 常购清单（高频补货）
| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 「常购清单」`/purchase/frequent` | 维护高频固定价量商品，可一键转申请 |

#### UC-PUR-03 询价 → 报价 → 比价定标（项目采购链路）
| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 「询价管理」`/purchase/inquiry` 发起询价（需审批） | 询价单生效 |
| 2 | 「报价管理」`/purchase/quotation` 下载模板→供应商报价→导入附件 | 各家价格展示 |
| 3 | 「比价定标」`/purchase/award` 选最优供应商、提交定标审批 | 审批通过后比价结果归档 |

**核对点（B4）**：报价导入若部分失败，可点「下载错误 Sheet」（`GET /api/v1/quotations/import/error-sheet/{batchNo}`，Redis 暂存 30min，流式 xlsx）。

#### UC-PUR-04 无申请来源询价（独立寻源 D9）
| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 发起询价时选「无申请来源」，填 `source_reason` | 必填校验 |
| 2 | 线下定标登记（填部门×科目） | **提交即占预算（锚点=award）** |
| 3 | 查看预算台账 | 对应科目行 `used` 增加（对账 `used=1000` 落科目行） |

**核对点（D9/CP-11）**：无申请来源的定标预算占用锚点 = `award`，不缺口。

#### UC-PUR-05 线下补录链路（D2）
| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 手填合同（`awardId=null`）→ 审批 | 合同登记成功 |
| 2 | 基于该合同、无采购申请（`applyId=null`）下单 | 跳申请头闸门/余量闸，**合同额度闸兜底** |
| 3 | 查看合同额度 | 合同 5000→4000 扣减对账 |

**核对点（D2/B6）**：无锚订单减额变更 `budget_occupied` 加 `max(0,…)` 下界，不落负值。

#### UC-PUR-06 日常采购授权 + 需求来源留痕 + 高频自动授权（D14/D16/D17）
| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 日常采购（无申请）下单，创建人不持授权 | 提示需授权确认；超阈值（默认 50 万占位）升级 `DAILY_AUTH` 审批任务 |
| 2 | 授权通过下单后查订单 | `authorized_by/authorized_name/authorized_time` 留痕；`source_type=OFFLINE`、`source_reason` 必填落库 |
| 3 | 开启 `app.order.daily-auto-auth-enabled=true`（高频补货） | 跳过人工升级任务，置 `auto_authorized=1`，**仍保留授权留痕**；合同/预算闸不跳过 |

**核对点（D14/D16/D17）**：
```sql
SELECT authorized_by, authorized_name, authorized_time, auth_over_limit,
       source_type, source_reason, auto_authorized
FROM purchase_order WHERE id = <订单ID>;
```
- `authorized_*` 非空；`source_reason` 非空（OFFLINE）；开启自动授权时 `auto_authorized=1`。

#### UC-SET-02 预付款结算 + 自动抵扣（D10）🟢
| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 从订单发起**预付款**结算（`payment_stage=PREPAYMENT`） | 类型可选"预付款" |

**核对点（D10）**：`payable` 取 `amount`（防双重扣减）；抵扣后尾款 ≤ 订单有效金额。

#### UC-SET-03 付款登记 + 冲销（G4）— 详见 `docs/G4_G2_功能验证测试用例.md` §3

| 3 | 已付(PAID)单冲销 | 同上，且不再参与对账口径 |

**核对点（G4/B9）**：`payment.status=3`；`sumPaidAmount`/`sumCommittedAmount` 自动排除 VOIDED。

## 4. 跨模块端到端主流程（三链路 + 结算闭环）

### E2E-1 日常采购链路（D1 + D14/D15/D16/D17）
```
常购/无申请 → 选「履行中且含价格清单」合同 → 系统校验(合同+预算+授权+供货范围)
   ├─ 普通：超阈值→DAILY_AUTH 升级审批→授权留痕→下单
   └─ 高频(开自动授权)：跳过人工升级→auto_authorized=1 仍留痕→下单
→ 订单(authorized_*/source_reason 非空) → 到货验收 → 物料结算 → 付款(可冲销)
```

### E2E-2 线下补录链路（D2）
```
手填合同(awardId=null) 审批 → 无申请下单(applyId=null, 合同额度闸兜底)
→ 预算占用锚点=award → 到货 → 结算 → 付款
```

### E2E-3 项目采购链路（询价→定标→合同→订单）
```
采购申请 → 询价(无申请来源 D9 占预算) → 报价导入(错误Sheet B4) → 比价定标(审批)
→ 合同登记(G2 经办信息 + D15 供货范围) → 订单(状态机 D11) → 到货 → 结算 → 付款(G4 冲销)
```

### E2E-4 预付款闭环（D10）
```
订单 → 发起预付款结算(PREPAYMENT) → 审批 → 实付
→ 尾款结算自动抵扣(prepaid_deduction) → 累计不超订单有效金额
```
