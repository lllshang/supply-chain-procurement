# 供应链采购协同中台 —— 需求评审报告

> 版本：v1.0（评审基线确认稿）
> 评审对象：本地《供应链需求清单_解析》（27 条功能点） × 飞书 PRD v1.1（2026-09-17）
> 角色：产品经理（许清楚）
> 结论先行：以 **PRD v1.1 作为统一需求基线**，本地清单作为功能点拆解输入；所有冲突项以 PRD 口径裁决，清单中冲突/缺失条目按本报告修正与增补。

---

## 一、评审结论概述

**1. 统一基线：采纳飞书 PRD v1.1 为唯一需求基线。**

**2. 采纳理由（结论先行）：**
- **口径更完整、闭环自洽**：PRD 已定义采购三链路（标准/项目、日常/框架、线下补录）及硬规则（订单必须基于已审批/登记且在有效期内的合同、定标只驱动合同不直接转单、预算为系统硬控制、申请可对应多订单、累计下单不超申请额度与合同可用额度），逻辑闭合、可生产化。
- **清单存在已确认冲突**：订单来源、采购模式、系统对接边界、H5 范围四处与 PRD 直接矛盾，且为外包视角罗列，未经产品闭环校验。
- **清单存在关键能力缺失**：SPU/SKU 多单位换算、审批单据中心、跨系统同步（Outbox/幂等/对账）、价格纠正、报表中心、履约调整、供应商产品绑定等 PRD 重点能力未覆盖，缺失将导致生产系统不可用或对账失败。
- **生产化边界已决策**：PRD 已对"不直连财务、经适配层解耦、跨系统同步方案已有未上线、H5 仅开放资质协同"等边界做出清晰决策，契合"原型→生产"所需的真实登录/权限/DB/事务/审批/跨系统同步要求。

**3. 二者关系定位：**
- PRD v1.1 = 需求基线（口径权威）。
- 本地清单 = 功能点拆解输入（需按本报告裁决表修正后使用）。
- 开发/架构拆解以本报告"第五节 需求池"为输入。

## 二、冲突项裁决表

> 标注：采用口径 / 理由 / 对开发的影响。优先级判定见第三节。

### 裁决 1：订单来源
| 项 | 内容 |
|---|---|
| 冲突点 | 清单「基于比价结果生成采购订单」 vs PRD「订单必须基于已审批/登记有效合同发起，定标只驱动合同不直接转单」 |
| 采用口径 | **采纳 PRD**。订单仅可由已审批/登记且在有效期内的合同发起；定标结果驱动合同登记，不直接生成订单；日常/框架链路订单基于有效合同发起、免比价。 |
| 理由 | 三链路硬规则明确，是采购合规与合同约束核心，避免无合同下单、超合同额度、定标与合同脱节。 |
| 对开发影响 | 采购订单"生成"入口改造为"选合同→带出可用额度/价格→发起订单"；删除"基于比价一键转单"；定标审批后落合同而非订单；实现合同-订单额度扣减与校验。 |

### 裁决 2：采购模式
| 项 | 内容 |
|---|---|
| 冲突点 | 清单「所有品类统一线下比价」 vs PRD 存在日常/框架合同免比价链路（清单漏掉日常与框架链路） |
| 采用口径 | **采纳 PRD 三链路**：①标准/项目链路走比价；②日常/框架链路基于有效框架/年度/定价协议发起订单，免比价、免采购审批，但强制校验合同+预算+授权，超预算/超授权/脱离合同价格范围须升级审批；③线下补录链路补录定标与合同后下单，不单设定标审批节点。 |
| 理由 | 真实业务存在复购与框架协议场景，强制比价不现实且低效；三链路覆盖完整业务，硬规则统一。 |
| 对开发影响 | 清单"采购模式"重写为三链路；报价/比价模块支持"可选/跳过"（日常框架链路跳过询价定标）；预算校验贯穿三链路；新增"合同价格范围/授权阈值"配置与升级审批触发。 |

### 裁决 3：系统对接边界
| 项 | 内容 |
|---|---|
| 冲突点 | 清单多处「对接审批中心/统一认证/零售餐饮系统」 vs PRD「一期不直连财务、跨系统同步方案已有但未上线、经适配层解耦」 |
| 采用口径 | **采纳 PRD 边界**。一期：审批中心经适配层/接口抽象承接（自建轻量审批单据中心 or 对接现有，待确认）；统一认证经适配层对接，账号权限由本系统组织权限模块管理；一期不直连财务，经 Outbox/适配层解耦；零售餐饮系统商品快速录入经接口提供，不做深度双向同步。跨系统同步（Outbox/幂等/对账）须设计但不一定一期全量落地（待确认）。 |
| 理由 | 一期聚焦采购闭环，避免被外部系统耦合拖慢；适配层解耦降低风险与返工。 |
| 对开发影响 | 所有对外依赖抽象为接口/适配层，审批、认证、财务、零售餐饮均不直接硬依赖；须设计 Outbox 事件表与对账机制（至少表结构与接口预留）。 |

### 裁决 4：H5 范围
| 项 | 内容 |
|---|---|
| 冲突点 | 清单仅提资质提交 vs PRD 明确 H5 当前仅开放资质协同，登录/订单/结算代码保留未路由 |
| 采用口径 | **采纳 PRD**。H5 一期仅开放：资质提交/审核/驳回重提。供应商登录、在线订单、在线结算代码保留但不路由（不在一期菜单暴露）。 |
| 理由 | 一期不开放供应商在线报价（走 Excel 报价包导出+后台导入），H5 收敛到资质协同，降低合规与数据风险。 |
| 对开发影响 | H5 仅交付资质提交/审核/驳回重提页面与接口；登录/订单/结算相关路由保留但默认关闭（feature flag 或菜单权限控制）。 |

### 裁决 5：清单缺失能力（增补裁决）
| 项 | 内容 |
|---|---|
| 冲突点 | 清单未覆盖 PRD 重点：SPU/SKU 多单位换算、审批单据中心、跨系统同步（Outbox/幂等/对账）、价格纠正、报表中心、履约调整、供应商产品绑定、采购申请物料/服务混合拆分等 |
| 采用口径 | **全部纳入本期（P0/P1）**。商品库须支持 SPU/SKU + 多单位换算（采购单位/基本单位，单据存换算快照）；建设审批单据中心承接审批任务与回写；跨系统同步设计 Outbox/幂等/对账（落地范围见待确认问题）；价格纠正（价格审核/历史价格库+纠错）；报表中心（采购统计等）；履约调整（到货/验收/部分入库/退货调整）；供应商产品绑定（供应商-商品目录绑定）；采购申请允许物料与服务混合，生成订单时拆分为物料订单/服务订单。 |
| 理由 | 这些是生产化采购闭环与治理的必需，缺失将导致系统不可用或无法对账。 |
| 对开发影响 | 商品模型扩展 SPU/SKU/单位换算；新增审批单据中心模块；新增集成/同步 Worker 与 Outbox 表；成本/价格模块扩展纠错；报表模块独立建设；采购申请/订单拆分逻辑。 |

## 三、统一后的功能范围（P0 / P1 / P2）

> P0 = 采购闭环（本期必交付）｜P1 = 已确认的效率与治理｜P2 = 架构预留（设计但不实现）

### P0 —— 采购闭环（一期必交付）
- 商品库管理：SPU/SKU + 多单位换算（采购单位/基本单位，单据存换算快照）、部门数据权限隔离、商品录入与价格修正权限独立。（修正清单：增补 SPU/SKU 与单位换算）
- 供应商入驻（平台方）：资质导入/审核、分类分级。
- 供应商入驻（H5）：资质提交/审核/驳回重提。（修正清单：明确仅资质协同，登录/订单/结算路由保留关闭）
- 合同管理：登记（须审批/生效且在有效期内方可发起订单）、到期预警、多维度检索。
- 预算管理：年度导入、月度调整、逐级分解、预算校验硬控制（部门+预算科目，超预算拦截并升级审批）。（修正清单：校验口径对齐 PRD）
- 采购申请：发起与审批（物料与服务混合，按部门负责人→预算校验→采购部审批，可驳回）。
- 采购模式（三链路）：标准/项目、日常/框架、线下补录。（修正清单：由"统一比价"改为三链路，见裁决 2）
- 采购订单：基于有效合同发起、免单设订单审批、带出合同可用额度/价格、按申请/合同校验、物料订单/服务订单拆分。（修正清单：订单来源改为合同，见裁决 1）
- 报价管理：询价、线下报价（Excel 报价包导出+后台导入，一期不在线报价）、定标审批（定标驱动合同不直接转单；线下补录链路不设单设定标节点）。
- 到货跟踪：到货确认、按实际数量部分入库、凭证上传。
- 结算管理：物料按验收结算、服务按质量考核结算、付款申请（结算从订单或到货单发起）。
- 审批单据中心：承接采购申请/合同/定标/预算升级等审批任务与回写。（清单缺失，PRD 重点）
- 组织权限/基础设置：组织（部门/供应商/业务板块）、角色菜单与操作权限、配置管理。（修正清单：统一认证经适配层）

### P1 —— 效率与治理（已确认）
- 跨系统同步：Outbox/幂等/对账，与零售餐饮/下游系统适配层解耦。（清单缺失，落地范围待确认）
- 报表中心：采购统计（部门/品类/供应商/时间）、成本分析。（清单仅"采购统计"，扩展为报表中心）
- 价格纠正与历史价格库：价格审核、纠错、价格库。（清单"价格审核"扩展）
- 履约调整：到货/验收差异、退货、订单变更调整。（清单缺失）
- 供应商产品绑定：供应商-商品目录/SKU 绑定。（清单缺失）
- 成本核算：按部门核算采购成本。（清单已有）
- 合同增强：批量操作、检索增强、预警策略可配置。

### P2 —— 架构预留（设计但不实现）
- AI 定价/预测（明确不做）。
- 完整 WMS（仅做到货验收/入库台账）。
- 第三方支付/银行直连（明确不做）。
- 供应商在线报价/在线结算/H5 登录订单（代码保留未路由）。
- 跨系统深度双向同步（二期）。

## 四、待确认问题清单（Open Questions）

> 以下为需主理人/相关方在开发启动前拍板的问题，至少 8 条（此处列 12 条）。

1. **跨系统同步一期落地范围**：Outbox/幂等/对账是仅设计预留，还是一期需实际支持与零售餐饮/下游系统的同步？首批对接系统清单与数据契约？
2. **审批中心方案**：一期自建轻量审批单据中心，还是对接现有企业审批中心？对接方式（API/事件）与回写协议？
3. **统一认证对接方式**：对接企业统一认证（SSO/LDAP/OAuth）还是本系统自带账号体系？账号同步与权限映射机制？
4. **Excel 模板规范**：报价包与预算导入模板的字段、校验规则、导入失败处理、版本管理，是否需供应商侧与财务侧共同确认？
5. **文件存储方案**：营业执照/合同/到货凭证等附件存储（对象存储选型、容量、合规留存期、与统一文件服务/云盘关系）？
6. **合同价格范围与授权阈值**：日常框架链路"脱离合同价格范围/超授权"的判定口径、阈值配置 owner、升级审批层级？
7. **预算控制粒度与来源**：是否仅部门+预算科目，是否关联项目/板块？一期不直连财务，预算数据如何获取/校准以保证一致性？
8. **多单位换算规则**：换算率由谁维护、变更历史如何管理、单据快照在验收/结算时的取数规则（取下单时快照 or 实时换算）？
9. **供应商产品绑定范围**：是否限定供应商仅能对其绑定商品目录报价/接单？与商品库 SPU/SKU 的关系？
10. **报表中心范围与数据源**：一期报表清单是否仅采购统计/成本分析/履约？是否需对接 BI？实时性要求？
11. **结算与财务衔接**：付款申请审批后"线下完成付款"，付款状态如何回写？是否需要付款台账与对账？
12. **数据迁移**：两个原型中的 Mock 数据、已存在供应商/合同/商品是否迁移到生产 DB？口径与责任方？
