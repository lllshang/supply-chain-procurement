## 0. 结论先行

P1 阶段交付三大主数据域的**模型 + 基础配置 + 启停用 / 校验规则**，是 P2（采购主链路）与 P3（预算硬控）的数据底座。本 Spec 已对齐 P0 已落地的 8 个实体（`spu / sku / unit_conversion / supplier / supplier_qual / supplier_sku / budget_header / budget_line`），明确其字段缺口与需新建的配置实体，**不触碰任何外部接缝（AuthProvider / ApprovalGateway / Adapter）**。

- **必须新增 7 个配置/主数据实体**：`product_category`（三级品类）、`unit`（单位配置）、`spec_option`（规格配置）、`price_rule`（价格规则）、`supplier_category`（供应商三级分类）、`budget_subject`（预算科目）、`budget_project`（预算项目）。
- **需在 6 个已有实体上加字段**：`spu`（图片/简介）、`sku`（采购单位/参考价/标准价/计件计重/图片）、`supplier`（合作状态/黑名单/来源/分类引用）、`supplier_qual`（资质名称/驳回原因/审核人/审核时间）、`supplier_sku`（供应商货号/供货价/包装单位）、`budget_line`（可选项目维度）。
- **关键跨模块契约**：供应商"准入资格"派生状态（行 14）与单位换算快照（行 8），本阶段只定义数据结构与查询接口，拦截点交由 P2/P3 在合同/订单/预算环节落地。
- **明确依赖**：行 13 资质 H5 提交属 P7，本阶段仅做后台资质管理与独立审核。

## 2. 产品目标（Product Goals）

1. **商品主数据底座**：建立 SPU/SKU/多规格/多单位换算/价格模型，使 P2 单据能引用准确商品并在下单时落"换算快照"，P3 能按正确口径占用预算。
2. **供应商主数据底座**：建立供应商档案/三级分类/等级/合作状态/黑名单/资质/商品绑定，使询价、定标、合同、订单能校验"供应商准入资格"并取供应商供货价。
3. **预算主数据底座**：建立预算科目/项目配置与年度预算（12 个月台账），使 P3 能按"部门 + 科目（+ 可选项目）"做预算硬控制。

> 三个目标正交：分别服务于"买什么""从谁买""花多少钱"，互不耦合，均为下游必备前置。

## 4. 需求池（按 P0 / P1 / P2 分级）

> 每条含：功能描述、验收标准（AC）、字段与状态约束、实体映射（已有 / +字段 / 新建）。
> 优先级定义：**P0 = 本阶段必交付（下游 P2/P3 强依赖）｜P1 = 本阶段效率/治理增强｜P2 = 架构预留（设计不实现）**。

### 4.1 产品管理（后台 / 产品管理）

#### P0 · R-PRD-01 产品库 SPU 管理
- **功能描述**：维护商品 SPU（商品定义），含 SPU 编码、名称、三级品类、规格、基本单位、主图、简介、启停用、备注。
- **AC**：① SPU 编码全局唯一且必填；② 三级品类必须从 `product_category` 叶子节点选择；③ 新建/编辑/停用/启用均可；④ 停用后该 SPU 下 SKU 不可在新单据引用（历史单据不受影响）。
- **字段与状态**：`spu` 已有 `spu_code/name/category_id/spec/base_unit/status/remark`；**+ `image_file_key`（主图，引用 `file_meta`）、+ `description`（简介，TEXT）**。`status`：0=正常 / 1=停用（已有）。
- **实体映射**：`spu`（+2 字段）。

#### P0 · R-PRD-02 SKU 与多规格
- **功能描述**：在 SPU 下维护 SKU（最小可交易单元），含 SKU 编码、条码、基本单位、规格值、主图、启停用。支持按规格组合生成 SKU。
- **AC**：① SKU 编码全局唯一；② 条码唯一（允许空，填则校验唯一）；③ 一个 SPU 下可有多 SKU；④ 规格以"规格名=规格值"结构化存储。
- **字段与状态**：`sku` 已有 `spu_id/sku_code/barcode/base_unit/spec/status`；**+ `image_file_key`**。
- **实体映射**：`sku`（+1 字段）；多规格组合策略见待确认 Q7。

#### P0 · R-PRD-03 多单位换算（采购单位↔基本单位）
- **功能描述**：为每个 SKU 配置采购单位与基本单位的换算率，含生效时间与版本，支持换算历史追溯。
- **AC**：① 一个 SKU 可配多条换算（不同采购单位→基本单位），但同一 `from_unit` 同一生效期仅一条有效；② 换算率 > 0；③ 变更产生新 `version` 并保留 `effective_from`；④ P2 单据落"换算快照"取自下单时当前有效版本（取快照而非实时换算，见架构待确认 8）。
- **字段与状态**：`unit_conversion` 已含 `sku_id/from_unit/to_unit/rate/effective_from/version`，**结构满足，无需加字段**（建议 + `status` 0=有效/1=失效，可选）。
- **实体映射**：`unit_conversion`（满足）。

#### P0 · R-PRD-04 采购单位 / 参考价 / 标准价 / 计件计重
- **功能描述**：SKU 维护采购单位（默认交易单位）、参考价、标准价，以及计价方式（计件/计重）。
- **AC**：① 采购单位必须在 `unit` 配置中存在且能经 `unit_conversion` 换算到基本单位；② 参考价/标准价 ≥ 0，DECIMAL(18,2)；③ 计价方式必选。
- **字段与状态**：`sku` **+ `purchase_unit`（采购单位，引用 `unit`）、+ `reference_price`（参考价）、+ `standard_price`（标准价）、+ `valuation_type`（0=计件 / 1=计重）**。
- **实体映射**：`sku`（+4 字段）。

#### P0 · R-PRD-05 产品启停用与数据校验
- **功能描述**：SPU/SKU 统一启停用；编码/条码/编码规则唯一性校验；必填与类型校验。
- **AC**：① 停用 SPU 联动其下 SKU 不可被新单据引用；② 编码/条码唯一冲突在保存时返回明确错误；③ 校验不依赖外部系统（纯本地）。
- **字段与状态**：复用 `status` 枚举；校验逻辑在 Service 层（非仅前端）。
- **实体映射**：已有，无新增。

#### P0 · R-PRD-06 三级品类配置
- **功能描述**：维护商品三级品类树（L1/L2/L3），SPU 必须挂在叶子节点。
- **AC**：① 树形三级，支持增删改；② 被 SPU 引用的品类节点不可删除（或置无效）；③ 编码唯一。
- **字段与状态**：**新建 `product_category`**：`id, parent_id, level(1/2/3), code, name, tree_path, status(0=有效/1=无效)`（继承 `BaseEntity`）。
- **实体映射**：**新建** `product_category`；`spu.category_id` 引用其叶子节点。

#### P0 · R-PRD-07 单位配置
- **功能描述**：维护计量单位字典（如 个/箱/千克/米），供采购单位/基本单位/包装单位引用。
- **AC**：① 单位编码唯一；② 被 SKU/换算引用的单位不可删除。
- **字段与状态**：**新建 `unit`**：`id, code, name, status(0=有效/1=无效)`。
- **实体映射**：**新建** `unit`。

#### P0 · R-PRD-08 规格配置
- **功能描述**：维护规格维度与可选值（如 颜色：红/绿；尺寸：S/M/L），供多规格 SKU 组合使用。
- **AC**：① 规格名唯一；② 可选值可维护；③ 被 SKU 引用的规格值不可删。
- **字段与状态**：**新建 `spec_option`**：`id, spec_name, spec_value, status(0=有效/1=无效)`（规格名可重复多行形成"名-值"对）。
- **实体映射**：**新建** `spec_option`。

#### P0 · R-PRD-09 价格规则配置（含引用校验）
- **功能描述**：配置价格规则（如最低限价/最高限价/区间），并能被商品或品类引用；保存时校验引用一致性。
- **AC**：① 规则类型可配置；② 商品/品类引用规则后，建档或修改价格超规则范围时给出校验提示（拦截或警告，见待确认 Q6）；③ 被引用的规则不可删。
- **字段与状态**：**新建 `price_rule`**：`id, rule_type, ref_type(商品/品类), ref_id, min_price, max_price, expression, status(0=有效/1=无效)`。
- **实体映射**：**新建** `price_rule`。

#### P1 · R-PRD-10 产品导入（单规格）
- **功能描述**：单规格商品模板导入（SPU + 单 SKU），服务端校验后落库。
- **AC**：① 模板带 `templateVersion`，版本不符拒绝并提示；② 字段/类型/业务规则（编码唯一、品类存在）校验；③ 失败行收集为"错误清单 Sheet"返回；④ 全部通过才落库（见架构 2.7）。
- **实体映射**：已有实体，无新增（导入服务新建）。

#### P1 · R-PRD-11 产品导入（多规格）+ 预览 / 错误定位
- **功能描述**：多规格模板导入，上传后返回预览（含规格组合展开），错误定位到行与列。
- **AC**：① 多规格行按规格组合展开为多条 SKU 预览；② 错误定位到具体单元格；③ 支持修正后重传。
- **实体映射**：已有，无新增。

#### P1 · R-PRD-12 产品导出（筛选）
- **功能描述**：按品类/状态/单位等条件筛选后导出 Excel。
- **AC**：① 导出列可配置；② 导出经数据权限拦截（部门隔离）；③ 大数据量异步导出（task_id 查进度，见架构 2.7 R1）。
- **实体映射**：已有，无新增。

### 4.2 供应商管理（后台 / 供应商管理）

#### P0 · R-SUP-01 供应商档案（三级分类 / 等级 / 合作状态 / 黑名单 / 来源）
- **功能描述**：维护供应商档案（名称、统一社会信用代码、法人、经营范围、联系人、电话、银行、三级分类、等级、合作状态、黑名单、来源），支持检索筛选。
- **AC**：① 统一社会信用代码唯一；② 三级分类从 `supplier_category` 选择；③ 合作状态可置 正常/停用/冻结；④ 黑名单可标记；⑤ 支持按名称/分类/等级/状态/黑名单组合检索；⑥ 所有写操作后端权限校验（`supplier:*` 权限）。
- **字段与状态**：`supplier` 已有 `name/credit_code/level/category/business_scope/contact/phone/bank_*` 与 `status`(SupplierStatus 资质状态)；**+ `supplier_category_id`（引用 `supplier_category`）、+ `coop_status`（合作状态 0=正常/1=停用/2=冻结）、+ `is_blacklist`（0/1）、+ `source`（来源：平台录入/H5提交/导入）**。
  - 说明：`status`（SupplierStatus：0=资质审核中/1=通过/2=驳回）保留为**资质状态**；`coop_status` 为**合作状态**；二者解耦，避免"资质审核中"误伤合作状态。
- **实体映射**：`supplier`（+4 字段）；**新建** `supplier_category`（三级供应商分类，结构同 `product_category`）。

#### P0 · R-SUP-02 供应商产品绑定（货号 / 供货价 / 包装单位）
- **功能描述**：批量绑定供应商与商品（SKU），维护供应商货号、供货价、包装单位；可选"限定报价/接单范围"开关。
- **AC**：① 同一供应商+SKU 仅一条有效绑定（唯一）；② 供货价 ≥ 0；③ 包装单位引用 `unit`；④ 绑定后，P2 询价/接单可按此范围限定（见待确认 Q9）；⑤ 批量绑定支持 Excel。
- **字段与状态**：`supplier_sku` 已有 `supplier_id/sku_id/price_range/status`；**+ `supplier_sku_code`（供应商货号）、+ `supply_price`（供货价 DECIMAL(18,2)）、+ `package_unit`（包装单位，引用 `unit`）、+ `bind_scope`（0=不限定/1=限定报价接单范围）**。`price_range` 可保留或迁移至 `supply_price`，建议以 `supply_price` 为准。
- **实体映射**：`supplier_sku`（+4 字段）。

#### P0 · R-SUP-03 资质管理（后台提交 / 独立审核 / 驳回重提）
- **功能描述**：后台可录入供应商资质（类型、附件、有效期）；独立资质审核（通过/驳回+原因）；驳回后供应商修改重提闭环。**H5 提交属 P7**，本阶段仅做后台管理与审核。
- **AC**：① 一个供应商可有多条资质（不同类型）；② 审核为独立动作（通过/驳回），不依赖采购审批流；③ 驳回必须填原因；④ 驳回后状态回到"待审"，供应商可修改重提（P7 H5 对接同一 `supplier_qual` 模型）；⑤ 审核人/审核时间留痕。
- **字段与状态**：`supplier_qual` 已有 `supplier_id/type/file_key/expire_at/status(0=待审/1=通过/2=驳回)`；**+ `qual_name`（资质名称）、+ `reject_reason`（驳回原因）、+ `reviewed_by`、`+ `reviewed_at`**。
  - 状态机：`待审(0) → 通过(1)` / `待审(0) → 驳回(2) → 待审(0)`（修改重提）。
- **实体映射**：`supplier_qual`（+4 字段）。

#### P0 · R-SUP-04 资质有效期状态与到期预警基础
- **功能描述**：基于 `supplier_qual.expire_at` 派生资质有效期状态（有效/即将到期/已过期）；建立到期预警基础数据（提前天数配置）。
- **AC**：① 派生状态实时计算：有效（未到期）、即将到期（≤ 预警提前天数）、已过期（已过 `expire_at`）；② 预警提前天数可配置（默认 30 天，见待确认 Q4）；③ 过期资质标记为失效，影响供应商准入（见 4.4）。
- **字段与状态**：`supplier_qual.expire_at` 已有；预警提前天数入配置（建议 `config` 表或 `price_rule` 同级配置实体，本阶段先定字段/接口，落地 P1）。
- **实体映射**：`supplier_qual`（满足）；预警配置（新建或复用配置表，待确认 Q4）。

#### P1 · R-SUP-05 资质到期预警通知
- **功能描述**：按预警提前天数向资质审核员/供应商管理员推送到期提醒（站内/邮件/短信）。
- **AC**：① 定时任务扫描即将到期资质；② 通知渠道与接收人可配置；③ 不阻塞采购闭环（预警仅提示，准入拦截见 4.4）。
- **实体映射**：无新增实体（通知走已有消息/邮件能力）。

### 4.3 预算管理（后台 / 预算与结算）

#### P0 · R-BUD-01 预算科目配置
- **功能描述**：维护预算科目（编码/名称/类型/层级），供预算明细引用。
- **AC**：① 科目编码唯一；② 支持层级（父/子）；③ 被预算明细引用的科目不可删。
- **字段与状态**：**新建 `budget_subject`**：`id, code, name, parent_id, subject_type(支出/收入), status(0=有效/1=无效)`。`budget_line.subject_id` 引用之。
- **实体映射**：**新建** `budget_subject`。

#### P0 · R-BUD-02 预算项目配置
- **功能描述**：维护预算项目（编码/名称/年份），作为可选预算维度。
- **AC**：① 项目编码唯一；② 项目维度为一期可选（见待确认 Q2）；③ 若启用，预算明细可按项目归集。
- **字段与状态**：**新建 `budget_project`**：`id, code, name, year, status(0=有效/1=无效)`。
- **实体映射**：**新建** `budget_project`；`budget_line`（+ `project_id` 可选，待确认 Q2 拍板后加）。

#### P0 · R-BUD-03 年度预算导入 + 12 个月台账
- **功能描述**：通过年度预算模板导入，生成预算头（年度/部门/总额）与预算明细（按科目、按 12 个月台账）。导入校验（模板版本、字段、科目/部门存在）。
- **AC**：① 模板带 `templateVersion`；② 导入生成 `budget_header`（1 条）+ `budget_line`（科目 × 月份，period 1–12，period=0 为年度总额）；③ `used_amount` 本阶段初始 0（P3 占用/核销写入）；④ 全部通过才落库，失败行回传错误 Sheet；⑤ 导入与部门数据权限一致。
- **字段与状态**：`budget_header` 已有 `year/dept_id/total_amount/status/remark`（满足）；`budget_line` 已有 `header_id/subject_id/period/amount/used_amount/version`（满足 12 个月台账：`period` 0=年度/1–12=月）。如启用项目维度，+ `project_id`。
- **实体映射**：`budget_header`/`budget_line`（满足）；`budget_subject`/`budget_project`（新建）。

#### P1 · R-BUD-04 预算"三种分解"策略
- **功能描述**：年度预算向科目/月份（及可选部门/项目）分解的三种策略。
- **AC**：① 策略口径需先拍板（见待确认 Q1）；② 分解结果写入 `budget_line`（period 维度）；③ 分解可重算（草稿态）。**口径未定，列为待确认，本阶段先建数据结构，策略实现待 Q1 拍板。**
- **实体映射**：已有，无新增。

### 4.4 跨模块契约（本期定义、下游落地）

#### P0 · R-X-01 供应商准入资格（派生状态）
- **功能描述**：定义供应商"准入资格" = 合作状态正常(`coop_status=0`) **且** 非黑名单(`is_blacklist=0`) **且** 关键资质有效（存在 `status=1` 且未过期的必要资质）。
- **AC**：① 提供查询接口 `GET /api/v1/suppliers/:id/admission`（返回 合格/不合格 + 原因）；② 本阶段仅计算与暴露，不做拦截；③ **拦截点由架构师在 P2（询价/定标/合同）与 P3 设计落地**（在发起询价、定标、建合同、下订单时校验该资格，不合格则拒绝）。
- **字段与状态**：依赖 `supplier.coop_status/is_blacklist` 与 `supplier_qual.status/expire_at`。
- **实体映射**：无新增；**提示架构师在 P2/P3 落拦截点（需求评审待确认 9 / 行 14）**。

#### P0 · R-X-02 单位换算快照契约
- **功能描述**：P2 单据（申请/订单/到货/结算行）下单时从 `unit_conversion` 取当前有效换算率存快照。
- **AC**：① 快照字段定义在 P2 设计；② 本阶段保证 `unit_conversion` 含 `version/effective_from` 可追溯（已满足）。
- **实体映射**：无新增。

## 7. UI 设计草稿（后台菜单结构）

后台 Web（Vue3 + Element Plus），菜单按角色权限（`supplier:*` / `catalog:*` / `budget:*`）控制：

```
产品管理
├─ 品类配置        (product_category 树)
├─ 单位配置        (unit 列表)
├─ 规格配置        (spec_option 列表)
├─ 价格规则        (price_rule 列表 + 引用校验)
├─ 产品库          (SPU 列表 → 展开 SKU / 多规格 / 单位换算 / 价格)
└─ 导入导出        (单规格导入 / 多规格导入预览 / 筛选导出)
供应商管理
├─ 供应商分类      (supplier_category 树)
├─ 供应商档案      (列表 + 检索筛选 + 档案抽屉)
├─ 供应商产品绑定  (供应商×商品 绑定表 + 批量绑定)
└─ 资质管理        (资质列表 + 独立审核 + 驳回原因 + 重提)
预算与结算
├─ 预算科目        (budget_subject 树)
├─ 预算项目        (budget_project 列表)
├─ 年度预算导入    (模板上传 + 校验 + 12 个月台账预览)
└─ 预算台账        (header + line 查询，period 维度)
```

> 页面风格遵循团队 Element Plus 设计令牌；列表页统一带部门数据权限过滤（后端 `DataPermissionInterceptor`），按钮权限后端校验。
